# Wedding Website — AI Build Prompts

> Purpose: These markdown prompts define the features, APIs, and data model for a small-footprint wedding website. Another AI agent should implement the app using **Next.js + TypeScript** (frontend) and **Spring Boot** with **SQLite** (backend), deployable on a single small Google Cloud instance.

---

## File: `00_overview.md`

### Objective

Build a secure, minimal, admin-configurable wedding website that:

- Imports a spreadsheet to seed a **guest list**.
- Sends **signup links** to guests to create accounts.
- Lets guests manage a **profile** (name, nickname, relation, photo).
- Displays **event pages** and a **timeline**.
- Enforces **per-guest access** (only see invited events/pages).
- Provides **admin impersonation** (“view as guest”).
- Supports **RSVP** per invited event + basic **travel options**.
- Has a configurable **homepage** and a **hamburger menu**.
- **Limits concurrent sessions** per user.

### Tech Constraints

- Frontend: **Next.js 14+**, App Router, **TypeScript**, React Server Components where helpful. Minimal dependencies.
- Backend: **Spring Boot 3+**, Java 17+, **SQLite** via JDBC. No heavy infra.
- Auth: **Email + password** (hashed server-side). **No email sending**. Registration uses **admin-issued invite codes**. Session-based auth on backend.
- Deployment: Single instance (frontend + backend) behind reverse proxy. Backend base URL configurable via env.

### Non-Goals

- No payments, no complex analytics, no social logins.

### Deliverables

- Working code, migrations, seed scripts, smoke tests. Follow prompts below.

## File: `01_frontend_pages.md`

### Generate These Pages (App Router)

1. `/` — **Homepage**

   - Shows hero title, welcome text, optional cover image, configurable in Admin.
   - If logged in: quick links to “My Events”, “Profile”, “RSVPs”.
   - If not logged in: prompt to **Enter Invite Code** (to register) and **Sign In**.

2. `/auth/signin` — **Email + Password Sign In**

   - Form: email, password.
   - Submit to backend `/auth/login`. On success, redirect to `/dashboard`.
   - Link to `Forgot password?` → `/auth/reset` (uses admin-issued reset code; no email).

3. `/auth/register` — **Register with Invite Code**

   - Step 1: Enter `inviteCode` and `email` (pre-filled if the code is bound to a specific email; if not, allow entry and validate against guest record).
   - Step 2: Set password (confirm password, strength meter). On success, account is activated, session created, redirect to `/dashboard`.

4. `/auth/reset` — **Reset Password (Code-based)**

   - Enter `resetCode`, `email`, new password, confirm password. Posts to `/auth/reset`.
   - Reset codes are generated by Admin and shared offline.

5. `/auth/change-password` — **Change Password** (protected)

   - Current password, new password, confirm new password.

6. `/dashboard` — **Guest Dashboard** (protected)

   - Cards: My Profile, My Events, My RSVPs (only invited events), Upload Photo.

7. `/profile` — **Profile Editor** (protected)

   - Fields: name, nickname, relation\_to\_{bride|groom}, photo upload.
   - Pre-filled from imported spreadsheet when available.

8. `/events` — **My Events (Timeline)** (protected)

   - Shows only events where the current guest is invited. Sorted by datetime.
   - Each item links to `/events/[id]`.

9. `/events/[id]` — **Event Detail** (protected)

   - Shows title, datetime, location, description, map embed, dress code.
   - RSVP widget (if invited) with travel options.

10. `/admin` — **Admin Home** (admin-only)

    - Cards: Upload Guests, Manage Events, **Invites**, Impersonate, Site Config, Password Resets.

11. `/admin/upload` — **Guest Import Wizard**

    - Step 1: upload CSV/XLSX. Step 2: column mapping. Step 3: validation summary. Step 4: commit.

12. `/admin/events` — **Events Manager**

    - CRUD events; assign invitees (multi-select); bulk actions.

13. `/admin/invites` — **Invite Codes**

    - Generate one-time **invite codes** per guest (or per household) with optional expiry; export as CSV/QR; revoke codes.

14. `/admin/impersonate` — **View as Guest**

    - Pick a guest; open a temporary impersonation session; banner indicating impersonation with “Return to Admin”.

15. `/admin/site` — **Site Config**

    - Homepage content (title, welcome, hero image URL), theme color, RSVP defaults, session limit.

16. `/admin/password-resets` — **Reset Codes**

    - Generate one-time **password reset codes** for selected guests; export/revoke.

### Navigation

- **Hamburger Menu** (mobile-first): Home, My Events, Profile, RSVP, (Admin if role=admin). Highlights current route.
- Sticky top bar with brand/logo; collapses to hamburger under `md:`.

### UX/State

- Use `SWR`/`fetch` for data fetching, `next/headers` for session cookie pass-through.
- Robust loading/empty/error states.
- Protected routes via server-side checks (redirect if not authenticated/authorized).

### Acceptance Criteria

- Registration requires a valid invite code; passwords are hashed server-side.
- Uninvited users cannot hit event pages.
- Admin can impersonate guests and see correct filtered data.
- Timeline only lists invited events.

## File: `04_backend_api_spec.md`

Build a Spring Boot REST API with session cookies. **Do not use JWT**; use HttpSession + Spring Security concurrent session control.

### Auth & Sessions (Password-based)

- `POST /auth/register` — body `{ inviteCode, email, password }` ⇒ validates invite code, creates/activates guest account (sets `password_hash`), logs in (creates session), invalidates invite code.
- `POST /auth/login` — body `{ email, password }` ⇒ verifies password, creates session cookie.
- `POST /auth/logout` — invalidates current session.
- `POST /auth/change-password` — body `{ currentPassword, newPassword }` (protected) ⇒ updates stored hash.
- `POST /auth/reset` — body `{ resetCode, email, newPassword }` ⇒ validates admin-issued reset code, updates hash, consumes code, creates session.

### Admin — Guests & Import

- `POST /admin/import/preview` — multipart file ⇒ returns column detection + sample rows.
- `POST /admin/import/commit` — body: mapping + fileRef ⇒ upsert guests.
- `GET /admin/guests` — list; filters (hasPassword, invited events, etc.).
- `PATCH /admin/guests/{id}` — update fields.

### Admin — Events

- `GET /admin/events` — list all.
- `POST /admin/events` — create.
- `PATCH /admin/events/{id}` — update.
- `DELETE /admin/events/{id}` — delete.
- `POST /admin/events/{id}/invitees` — body: `{ guestIds: UUID[] }` — replace or merge assign.

### Admin — Invite Codes (Registration)

- `POST /admin/invites/generate` — body: `{ guestIds: UUID[], expiresAt?: string }` ⇒ creates one-time codes, returns masked representations and export handle.
- `GET /admin/invites` — list codes with status and expiry; filter by guest.
- `POST /admin/invites/revoke` — body: `{ codeIds: UUID[] }` ⇒ revoke.
- `POST /admin/invites/export` — body: `{ codeIds?: UUID[], format?: 'csv'|'qr-pdf' }` ⇒ returns downloadable artifact id.

### Admin — Password Reset Codes

- `POST /admin/resets/generate` — body: `{ guestIds: UUID[], expiresAt?: string }`.
- `GET /admin/resets` — list.
- `POST /admin/resets/revoke` — revoke.

### Admin — Impersonation

- `POST /admin/impersonate/start` — body `{ guestId }` ⇒ creates impersonation session (stores `impersonatingAs`), returns ok.
- `POST /admin/impersonate/stop` — ends impersonation, restores admin session.
- All responses include header `X-Impersonating-Guest-Id` when active.

### Admin — Site Config

- `GET /admin/site-config`
- `PUT /admin/site-config`

### Guest — Self Service (requires session)

- `GET /me` — returns current guest profile + invited events.
- `PATCH /me` — update own profile (excluding email unless Admin change is allowed policy-wise).
- `POST /me/photo` — upload profile image (multipart). Returns `profilePhotoUrl`.
- `GET /me/events` — only invited events.
- `GET /me/events/{id}` — event detail if invited.
- `GET /me/rsvps` — RSVPs for invited events.
- `PUT /me/rsvps/{eventId}` — upsert RSVP for that event.

### Rate Limiting & Session Concurrency

- Enforce **maxConcurrentSessions** (from SiteConfig) via Spring Security `ConcurrentSessionControlAuthenticationStrategy`.
- Add **login attempt throttling** (e.g., per IP and per account) with exponential backoff.

### Responses & Errors

- Use problem+json for errors. Return 401 for unauthenticated, 403 for unauthorized.

## File: `06_invite_codes_and_passwords.md`

### Registration Without Email

1. Admin imports guests.
2. Admin generates **invite codes** (one-time) per guest from `/admin/invites` with optional expiry (e.g., 14 days).
3. Codes can be exported as **CSV** or **QR** and shared via WhatsApp/print, etc.
4. Guest visits `/auth/register`, enters `inviteCode` and `email` (must match the guest record if bound), sets **password**.
5. On success, the code is consumed, `password_hash` is stored, and the user is signed in.

### Password Resets (No Email)

- Admin generates **reset codes** in `/admin/password-resets` on request from a guest and shares them offline.
- Guest uses `/auth/reset` with the reset code to set a new password.

### Security

- Codes are random (at least 128 bits of entropy), stored **hashed** with expiry; comparison via constant-time check.
- Throttle attempts per IP and per code id.
- Passwords hashed with **BCrypt (cost ≥ 12)** or **Argon2id**; consider an application-level **pepper** from env.

## File: `08_access_control_and_impersonation.md`

### Access Control Model

- **Authenticated Guest**: can only read/update own profile; view only invited events; RSVP only for invited events.
- **Admin**: full CRUD on guests/events/invitations/site config; can start/stop impersonation sessions.

### Enforcement

- Backend filters all `/me/*` endpoints by `session.guestId`.
- Event detail checks membership in `event_invitees`.

### Impersonation

- Start: stores `session.impersonatingAs = {guestId}` while preserving admin id in `session.adminId`.
- All `/me/*` calls read effective guest id from impersonation if set.
- Responses include `X-Impersonating-Guest-Id` header.
- UI banner with “Return to Admin”. Audit log (optional) records starts/stops.

## File: `10_session_limits_and_rate_limits.md`

### Concurrent Sessions

- Use Spring Security concurrent session control. Default `maxConcurrentSessions = site_config.max_concurrent_sessions` (default 2).
- On new login when limit reached: **invalidate oldest session** and proceed, with notification to user. Admin-configurable toggle to **block instead**.

### Request Rate Limiting (Optional)

- Lightweight in-memory token bucket per IP with sliding window; 60 req/min default.
- **Login/registration throttling**: backoff on failed attempts; temporarily lock account after N consecutive failures.
- Return `429 Too Many Requests` with `Retry-After` where appropriate.

## File: `16_build_notes_for_ai_agent.md`

When generating code:

- Keep functions small and pure; add docstrings.
- Align TypeScript and Java DTOs to contracts above.
- Centralize fetchers on frontend; handle 401/403 with redirects.
- Provide seed data and an `admin@local` seeded account **with a pre-hashed password**.

- For password hashing: use **BCrypt** via Spring Security (or Argon2). Configure strength and test.
